# WH120 老化脚本

WH120 灵巧手的四种老化动作，外加空载老化前的一道**判合格工序**，用官方 Python SDK
写成五个独立脚本。

**动作参数与产线上位机 `sboard_qt` 一致** —— 频率、增益、运动范围、逐轴防撞限幅、
停机时序都是照着上位机的实现搬的，对照关系见第 4 节。默认老化时长 **2 小时**，
和上位机老化计时器的达标阈值（120 分钟）一致。

> 只有一处**故意不一致**：四指二轴（外展）的摆幅默认 ±20°，让每根手指的二轴都参与
> 老化；上位机那个开关出厂是关的。加 `--abd-swing-deg 0` 即可复刻上位机默认。

**四种老化动作**（只跑动作，不出合格结论 —— 判据规格见第 10 节）：

| 脚本 | 做什么 | 频率 | kp / kd / 扭矩上限 | 上位机对应 |
|---|---|---|---|---|
| `no_load_aging.py` | 空载老化：整手全幅正弦往复 | 0.3 Hz | 5 / 0.1 / 1.0 A | `SweepWorker::doStartAging` |
| `grasp_aging.py` | 带载老化：张开 ↔ 抓握圆柱开合 | 0.25 Hz | 5 / 0.1 / 1.5 A | `SweepWorker::doStartGrasp` |
| `single_joint_aging.py` | 单关节老化：全行程走极限 | 0.5 Hz | 5 / 0.1 / 1.0 A | `SweepWorker::doStartSingleJointAging` |
| `single_finger_aging.py` | 单手指负载老化：17 段梯形序列 | 一圈 35 s | 3 / 0.1 / 1.5 A | `SingleFingerLoadAgingController` |

**一道判合格工序**（跑完直接出 PASS / FAIL，用退出码和 JSON 给出）：

| 脚本 | 做什么 | 时长 | kp / kd / 扭矩上限 | 上位机对应 |
|---|---|---|---|---|
| `pos_perf_qc.py` | 位控性能QC：逐指测跟踪延迟 + 指尖静差 | 5 指约 3~5 分钟 | 8 / 0.2 / 1.5 A | `PosPerfQcWorker` |

另有 `set_hand_ip.py` 改手 IP，多只手同时用时才需要。

### 产线工序顺序：位控性能QC 在空载老化**前面**

上位机里空载老化前面还有两道工序，本工程只覆盖了后一道：

| 上位机工序 | 本工程 | 说明 |
|---|---|---|
| ① 相序检查 | **没有** | 要逐关节读 `od/ucfg/module_id` + `od/enc1_phase_sequence_active` 再跟固件 catalog 基准比。**公开 SDK 没有原始对象字典读接口**，复刻不了 —— 这道工序仍需在上位机上做 |
| ② 位控性能QC | `pos_perf_qc.py` | 判据与两处差异见第 12 节 |
| ③ 空载老化 | `no_load_aging.py` | |

**两个脚本互相独立，`no_load_aging.py` 不会自动先跑 QC。** 顺序由调用方负责，
自动化设备这样串（**`rc != 0` 一律不往下走**）：

```python
rc = run("pos_perf_qc.py --out qc.json")
if rc != 0:                      # 1=不合格  2=连接/参数错  3=判不了
    abort("位控性能QC 未通过，不进老化")
run("no_load_aging.py --duration 2h")
```

> 退出码 `3`（判不了，典型是限位表没标定）最容易漏 —— 它不是「合格」，但也不是
> 「不合格」。写成 `if rc == 1: abort` 就会把这批手放过去，等于没卡。

### 上位机有两套老化，本工程对标的是「扫频」那套

`sboard_qt` 里并存两条完全不同的老化路径，**看到的动作差别很大**，别搞混：

| | **扫频老化**（本工程对标） | **Sin 运动老化** |
|---|---|---|
| 谁在跑 | 上位机 200 Hz 广播 MIT 指令 | **关节 MCU 自跑**（`pl_test`），不依赖上位机 |
| 代码 | `SweepWorker::doStartAging` | `SinAgingWorker::doStartSin` |
| 限位来源 | `NidRangeTable` | 逐关节读 `od/ps_final_pos_*` 真限位 |
| 幅度 | 全行程 −5°，另加三条防撞内缩；**四指二轴单独控制** | 每轴一律 **全行程 −5°**，二轴一视同仁 |
| 频率 | 0.3 Hz | 0.5 Hz |
| 增益 | kp 5 / kd 0.1 / iq 1.0 | **无 kp/kd**（固件位置环），iq 1.5 |
| 相位防撞 | 拇指 π、四指 J3/J4 π | 无，各关节各跑各的 |

**Sin 运动老化用公开 SDK 复刻不了** —— 它要写 `od/aux/pl_test_*` 再用 `aux_function[4,1]`
启动，这些原始对象字典操作 SDK 没有暴露。

但它的**运动包络**本工程有等价的：`single_joint_aging.py` 就是每轴全行程 −5° + 0.5 Hz，
和 Sin 老化逐轴一致。所以：

> **想看到四指二轴大幅摆动（±35° 那种），跑 `single_joint_aging.py`，不是空载老化。**
> 空载老化（扫频）的二轴按上位机设计本来就只有小幅摆动或锁死。
> 配 `--iq 1.5` 可与 Sin 老化的扭矩上限对齐；差别只剩「我们多做了相位防撞」。

## 1. 装

唯一的第三方依赖是官方 `wuji-sdk`。**它既不在公共 PyPI 上，也没有发布到 GitHub
Releases** —— 那边的 release 只有 C SDK 的 `.tar.gz`（android / linux-gnu），从没有过
Python wheel。Python 包是从 SDK 源码仓库用 maturin 编出来的：

```bash
# 内部源码仓库 wuji-sdk-dev, 用 maturin 构建当前平台/Python 版本的 wheel
maturin build --release          # 产物在 target/wheels/
pip install target/wheels/wuji_sdk-<版本>-cp3xx-cp3xx-<平台>.whl

# 装完自检
python -c "import wuji_sdk; print('ok')"
```

**没有构建环境就找 SDK 维护方要一个对应平台的 wheel** —— 它是 Rust 编译产物，
跨平台/跨 Python 版本都不通用（本机这份是 `cp313-cp313-win_amd64`）。

> **别指望 `pip install -r requirements.txt`** —— 那个文件是依赖**说明**，不是可安装
> 清单（唯一那行依赖是注释掉的）。`wuji-sdk` 这个名字在公共 PyPI 上无人注册，写成真
> 依赖行的话，哪天被抢注就会从公共源拉到同名的陌生包。

**Python ≥ 3.10**（SDK 的 `Requires-Python` 就是 3.10，3.9 装不上）。本工程自己的代码
只用标准库（`argparse/json/math/os/signal/sys/threading/time/dataclasses/typing`），
**不用安装**，解压进目录直接跑。

真机验证过的组合：**wuji-sdk 2026.8.17** / Python 3.13 / Windows x64。
（2026.7.21 也验证过；错误码解码需要 ≥ 2026.8.17，老版本自动退回只打十六进制。）

电脑有线网卡设成和手同网段：IP `192.168.1.100`，掩码 `255.255.255.0`，网关 `192.168.1.1`。
手上电后要等约 40 秒才就绪。

## 2. 跑之前必须知道的 5 件事

1. **Ctrl+C 只按一次。** 按一次是安全停机（收摆 → 回零 → 断使能），约 5 秒。
   按第二次是强制退出，电机会停在当前姿态。
2. **换手、换治具、改完轨迹，先小幅试。** 先 `--dry-run` 看行程，再 `--amp-scale 0.2`
   跑一分钟确认手指不打架，最后才满行程。
3. **空载老化启动前先把四指手动撑成扇形。** 脚本默认锁定启动瞬间的姿态（和上位机
   「四指手动撑开」默认开启一致），四指并拢着蜷曲会互相剐蹭。不想靠人撑就加
   `--abd-mode preset`（自动摆扇形）。
4. **单指负载老化挂着负重块时别强杀进程。** 停机时要先把扭矩上限 2 秒内缓降到 0 A
   才断使能，直接杀进程等于手指自由落体。
5. **上位机连着这只手的时候，脚本连不上。** 设备并发会话很少，先在上位机上断开。
   见第 8 节。

## 3. 三步跑起来

以空载老化为例，其它脚本换个名字就行。

**第一步，先看不动手**

```bash
python no_load_aging.py --dry-run
```

打印每个关节实际会走到的角度。看最后一列「余量°」—— 它是离机械限位还剩多少，
**出现负数或 `<<< 超限!` 就别跑**：

```
档案 空载老化 (整手扫频 0.30Hz): kp=5.00 kd=0.100 iq=1.00A, 使能 20 关节, 周期 3.33s
  joint             cmd_min°  cmd_max°  lim_min°  lim_max°     余量°
  thumb_J1             -63.0      69.0     -68.0      74.0     5.0
  index_J3             -55.0     110.0     -60.0     120.0     5.0
  ...
```

**第二步，小幅试跑**

```bash
python no_load_aging.py --amp-scale 0.2 --duration 60s
```

只走 20% 行程，跑 1 分钟自动停。盯着手看方向对不对、手指会不会碰。
没问题就逐步放大（0.2 → 0.5 → 1.0）。

**第三步，正式跑 2 小时**

```bash
python no_load_aging.py --duration 2h
```

2 小时是上位机老化计时器的达标阈值（`agingTargetMinutes` 默认 120 分钟）。
不写 `--duration` 就一直跑到 Ctrl+C。跑起来长这样，中间每分钟报一次状态：

```
发现 WH2JA01260723023 @ 192.168.1.110:7447
[WH2JA01260723023] 已连接 SN=... 手型=left 在线关节=20/20
[WH2JA01260723023] 使能 20 个关节: ...
[WH2JA01260723023] 回零/就位斜坡 (3.0s)
[WH2JA01260723023] 开始老化循环 —— Ctrl+C 停止 (会自动收摆回零后断使能)
[WH2JA01260723023] 已跑 1 分钟 | 母线 11.7V(最低 11.5V) 电流峰 0.34A 温度 41℃(最高 41℃)
[WH2JA01260723023] 已跑 2 分钟 | 母线 11.7V(最低 11.5V) 电流峰 1.01A 温度 45℃(最高 45℃)
        ...
[WH2JA01260723023] 老化循环结束, 累计 120.0 分钟 (1440000 拍, 掉拍 0 次)
[WH2JA01260723023] 整场汇总: 母线最低 11.5V, 电流峰 1.08A, 温度最高 52℃, 全程无错误码
[WH2JA01260723023] [停止] 沿原轨迹收摆 (1.0s)
[WH2JA01260723023] [停止] 停稳保持 (0.5s)
[WH2JA01260723023] [停止] 柔顺回零 (2.0s)
[WH2JA01260723023] 已断使能

```

- **掉拍** 不为 0 = 电脑跟不上 200 Hz 命令率，关掉别的占 CPU 的程序。
- **母线电压** 正常 11~12 V。掉到 10 V 以下说明多个关节堵转或撞在一起了，赶紧停。
- **电流峰** 是**这一分钟内**的峰值（不是抓拍瞬时值），每行重新统计；末尾汇总那行是整场峰值。
- **温度** 是关节 MCU 温度，取全手最高的那个。**看趋势，别看绝对值** —— 没有公开的
  温度阈值，而且起始温度取决于这只手之前跑了多久。实测两只手空载 20% 行程跑 1 分钟，
  最高温分别是 51 ℃ 和 67 ℃，差得很远（后者之前一直通着电）。正常是爬一段后走平，
  一路不停往上爬才是问题。
- **出问题的时候这行会变长**，多出限幅和错误码字段，怎么读见第 8 节。

老化循环结束时还会打一行**跟踪检查** —— 把每个轴的命令行程和**实际走到的行程**对比：

```
跟踪检查: 20 个运动轴实际行程都 ≥ 命令的 80%
跟踪检查: 1 个轴实际行程 < 命令的 80% (其余 19 个正常):
    ring_J2        命令   6.0° → 实际   4.2°  (70%)
```

命令发出去不等于关节跟得上：小振幅 + 低 kp 的轴（典型就是四指外展）可能被静摩擦吃掉
大半，光看日志里的「±20°」会以为在动，肉眼却看不出来。**觉得某个轴没动，先看这一行。**

## 4. 运动范围：和上位机的对应关系

这一节是「跑出来的效果和上位机一样」的依据。**不写 `--amp-scale` 时，脚本走的就是
上位机的行程**，`--amp-scale` 只是给试跑用的缩放，正式老化不要带。

**空载老化 / 单关节老化** —— 每个关节在**自己的限位内全幅**摆，不是固定角度：

```
中心 = (lim_min + lim_max) / 2
振幅 = (lim_max - lim_min) / 2 - 5°      ← 两端各留 5° 余量
```

在这个基线上，**只有整手空载老化**再加三条逐轴内缩（防止极限姿态戳掌心）：

| 关节 | 内缩 | 效果（用本工程的设计限位算） |
|---|---|---|
| 拇指 J2（CMC 外展） | 外展端 25°、对掌端 30°（**不对称**，中心要按生效边界重算） | `-85~40°` → `-60~10°` |
| 拇指 J3（MCP） | 蜷曲端 10° | `-60~90°` → `-55~80°` |
| 四指 J3（PIP） | 蜷曲端 10° | `-60~120°` → `-55~110°` |
| 其余所有轴 | 只有两端各 5° | 如拇指 J1 `-68~74°` → `-63~69°` |

**单关节老化不加这三条**，保持全幅 —— 和上位机一致（上位机的理由是单关节一次只勾
一两个轴，不存在指间干涉）。所以这个脚本整手跑时行程比空载老化大，务必先
`--amp-scale 0.3` 确认。

**相位防撞**（两个脚本都有，和上位机同一套）：

- 拇指 J1/J2 反相 π —— 四指往掌心蜷时拇指外展躲开。**左右手都给 π**。
- 四指 J3/J4（PIP/DIP）与 J1（MCP 屈）反相 π —— 形成「勾」形，指尖被推到远端不戳掌心。

**每根手指的二轴（外展）默认都动。**

- **拇指二轴**（CMC 外展）本来就是老化的一部分：空载老化里走全幅正弦（带上表的
  25°/30° 非对称内缩），带载老化里跟着抓握↔张开走。和上位机一致。
- **四指二轴**（mcp_abd）分成**中心**和**摆幅**两件独立的事，和上位机的两个开关
  一一对应：

| | 上位机 | 本工程 | 默认 |
|---|---|---|---|
| 中心在哪 | `fourFingerAbdManual` | `--abd-mode manual` / `preset` / `fan` | `manual` = 锁定启动瞬间的手动撑开位 |
| 摆多大 | `fourFingerAbdSwingEnabled` + `fourFingerAbdSwingDeg` | `--abd-swing-deg` | **20°**（逐指分级：食/中满摆、无名 ×0.6、小指 ×0.5） |

> ⚠ **摆幅默认值是本工程唯一一处故意偏离上位机的地方。** 上位机的摆动开关出厂
> **默认关**（二轴锁定不动），本工程默认 **±20°**，让每根手指的二轴都参与老化。
> 要完全复刻上位机出厂行为就加 `--abd-swing-deg 0`。
>
> 20° 是在本工程的手上实测标定过的：空载 20/20 轴跟踪达标、母线 11.3 V；带载
> 全程无限幅、母线 11.4 V。上位机那个旋钮的默认值是 5°、上限 30°。**换一只手、
> 换一套治具仍要重新标定**，从小往大加。

四种组合都能表达（上位机 `SweepWorker.cpp` 里 `ampK` 与 `manualAbd` 是分开算的，
中心和摆幅互不影响）：

| 命令 | 效果 |
|---|---|
| 默认 | 锁定手动撑开位 + 摆 ±20° |
| `--abd-swing-deg 0` | 锁定手动撑开位，不摆（＝上位机出厂默认） |
| `--abd-mode preset --abd-swing-deg 0` | 扇形预设常量，不摆 |
| `--abd-mode fan` | 按本手设备限位张最大扇形 + 摆 ±20° |

**带载老化** —— 抓握姿态表 × 深度/张开百分比，默认 `--depth 60 --release 30`、
0.25 Hz，这三个和上位机一致。四指二轴同样默认摆 ±20°，**开摆动时会覆盖**抓握姿态表
给这四个轴算的开合（和上位机 `doStartGrasp` 一致）；`--abd-swing-deg 0` 则回到跟随
抓握开合。带载时四指没有物理负载压着，可以自由张开摆。

**单指负载老化** —— `J1 ±45° → J3 ±45° → J4 ±45° → (J1 屈到 +90° 保持) J2 ±35°`。
这套角度**不留 5° 内缩余量**（和前面三个脚本不同），因为 +90° 正好就是四指 J1 的
设计上限。拇指例外：cmc_flex 上限只有 +74°，硬发 +90° 会每圈顶死 3 秒，所以脚本会
自动按限位削幅并打印削到多少。

> **这些行程用的是设计限位，上位机用的是设备实测限位。** 上位机读固件里每只手自己的
> 真限位（`ps_final_pos`），`WujiHand2` 在公开 SDK 上读不到，所以本工程默认用图纸设计
> 值 —— 实测发现有的轴设计值比真限位宽了 17°，满行程跑会顶死。**跑一轮
> `--export-limits` 把真限位测出来**，之后脚本按 SN 自动认这只手的表，行程就和上位机
> 一致了。见第 9 节。

## 5. 各脚本怎么调

每个脚本 `--help` 里都有自己的例子。不写 `--address` 就自动扫描，扫到几只手同时跑几只。

**位控性能QC**（空载老化的前道工序，**判合格**，不是老化）

```bash
python pos_perf_qc.py --dry-run          # 先看每轴行程和限位余量, 不使能不运动
python pos_perf_qc.py                    # 正式跑全部在线手指, 约 3~5 分钟
python pos_perf_qc.py --finger index     # 只测食指
python pos_perf_qc.py --out qc.json      # 结果写 JSON, 给自动化设备取数
python pos_perf_qc.py --lag-ms-max 37    # 按「扣掉 bridge 偏移」的严门限判
```

判据、退出码、与上位机的两处差异**全在第 12 节**，上产线前请先读那一节。
几个和老化脚本不同的地方：

- **不支持 `--export-limits`** —— 它靠「被限位夹住」反推真限位，而位控QC 一旦夹住
  就该判「判不了」，两件事冲突。要标定限位用 `single_joint_aging.py`。
- **`--duration` 只当超时兜底**，不是运行时长（跑完自己就停）。
- **`--amp-scale` 一带上，结论就作废**（记成「判不了」）。它只用来先确认方向和干涉。

**空载老化**

```bash
python no_load_aging.py --duration 2h                     # 正式老化(四指二轴默认摆 ±20°)
python no_load_aging.py --abd-mode preset --duration 2h   # 四指中心自动摆扇形, 不用手撑
python no_load_aging.py --abd-swing-deg 0 --duration 2h   # 四指二轴锁死不动(上位机出厂默认)
python no_load_aging.py --abd-mode fan --abd-swing-deg 3  # 按设备限位张最大 + 摆 ±3°
```

`--abd-mode` 管四指外展**中心**：`manual`（默认，锁住启动时的姿态）/ `preset`（实测
采集的扇形预设）/ `fan`（按本手限位张到最大扇形；旧名 `swing` 仍可用）。
`--abd-swing-deg` 管**摆幅**，默认 20°，和中心模式自由组合。详见第 4 节。

**带载老化**

```bash
python grasp_aging.py --duration 2h
python grasp_aging.py --depth 80     # 细圆柱, 握深一点 (默认 60)
python grasp_aging.py --release 0    # 每次完全张开伸直 (默认 30)
python grasp_aging.py --abd-swing-deg 0    # 四指外展跟随抓握开合(上位机出厂默认)
python grasp_aging.py --abd-mode fan       # 四指中心改成按设备限位张最大扇形
```

`--depth` 抓握深度 %：粗圆柱调小、细圆柱调大。
`--release` 张开程度 %：0 = 完全伸直，100 = 一直握着不松。
`--abd-mode` / `--abd-swing-deg` 同空载老化（少一个 `preset`），默认摆 ±20° 且**覆盖**
抓握姿态表给四指外展算的开合。详见第 4 节。

**单关节老化**

```bash
python single_joint_aging.py --duration 2h         # 跑全部在线关节
python single_joint_aging.py --joints index_J3     # 只跑食指 J3
python single_joint_aging.py --joints thumb,index_J3
```

`--joints` 写法：`index`（整根手指）/ `index_J3`（单个轴）/ `nid:8`（固件 NID）/
`6`（0~19 的下标），逗号分隔。不写就跑全部在线关节。

> 行程比空载老化大（少了第 4 节那三条内缩），**整手跑之前一定要先 `--amp-scale 0.3`
> 确认不剐蹭**。长时间空载耐久请用空载老化。

**单手指负载老化**

```bash
python single_finger_aging.py --duration 2h           # 跑全部在线手指(治具盒上通常就一根)
python single_finger_aging.py --finger index          # 只跑食指
python single_finger_aging.py --finger index,middle   # 食指 + 中指
```

`--finger` 逗号分隔，写 `thumb` / `index` / `middle` / `ring` / `pinky`。

> `--dry-run` 里四指 J1 的**余量会是 0.0°** —— 保持相位的 +90° 正好等于设计限位 +90°，
> 命令角顶着限位走，这是序列本身如此，不是异常（拇指会被削到 +74°）。但限位表是设计
> 值（第 9 节）：这只手的实际限位若比设计值小哪怕一点，+90° 就会顶死 → 持续限流堵转。
> 所以这个脚本尤其要看状态行里的 `限流`，一直亮就把 `--amp-scale` 降下来。

整只手都在线时会 5 根一起跑，而这套角度是单指治具上标定的（前提是旁边没有别的手指），
所以脚本会提示先小幅确认。

## 6. 通用参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--address IP:PORT` | 自动扫描 | 设备地址，**可重复 = 一拖多**。端口是 `7447` |
| `--duration T` | 一直跑 | 跑多久自动停：`90s` / `30m` / `2h`。老化用 `2h` |
| `--amp-scale K` | `1.0` | 行程缩放 0~1，只缩摆幅不动中心位置。**试跑用，正式老化别带** |
| `--dry-run` | 关 | 只打印行程，不使能不运动 |

| `--limits FILE` | 按 SN 自动找 | 强制指定限位表。**一般不用写**，见第 9 节 |

| `-v` | 关 | 打印 SDK 内部日志，连不上或掉线时用 |

## 7. 多只手一起跑

四个脚本都支持。一台电脑 + 一台交换机最多带 4 只手，左右手任意组合。

**先配 IP。** 出厂 IP 按左右手写死：所有左手 `192.168.1.110`，所有右手 `192.168.1.111`。
所以**同侧**两只手一起上电会撞 IP，谁都连不上。

| 情况 | 怎么配 |
|---|---|
| 1 左 1 右 | 不用配 |
| 每侧第一只 | 用默认，不用配 |
| 同侧第 2、3、4 只 | 各改一个空闲 IP：`.112` / `.113` / `.114` |

逐只配，**一次只上电一只手**（同侧默认 IP 相同，同时上电会撞车；脚本扫到多于一只
会直接拒绝）：

```bash
# 只给这一只上电, 等 40 秒
python set_hand_ip.py --show          # 先确认连得上: SN / 手型 / 当前 IP / 在线关节
python set_hand_ip.py --ip 192.168.1.112
# 会弹 [y/N] 确认, 敲 y 回车; 批量配可以加 -y 跳过
# 看到 [成功] 后断电, 换下一只
```

目标 IP **必须和当前 IP 同 /24 网段**（固件的子网/网关写死成 `255.255.255.0` + `.1`），
写成 `192.168.2.x` 会被脚本直接拒绝 —— 真改过去就只能拆机救回来。`.0` / `.1` / `.255`
同样拒绝。改之前脚本还会扫一遍网段，确认目标 IP 没被别的手占着。

配好的 IP 存在设备里，断电不丢。**手离开工站或发货前记得复位**：

```bash
python set_hand_ip.py --reset-default
# 旁边还有别的手在线时 autoscan 会拒绝, 得指明是哪一只:
python set_hand_ip.py --address 192.168.1.112:7447 --reset-default
```

`set_hand_ip.py` 的选项就这些：`--show` / `--ip` / `--reset-default`（三选一，必填）、
`--address`、`-y`、`-v`。退出码：成功 0，参数或设备报错 2，Ctrl+C 130。

> 写 IP 是 **deferred-apply**：`--ip` 先把新地址写进 flash，重启后才生效。所以 SET
> 之后、重启完成之前读到的仍是旧 IP，**这不是 bug**，脚本会自己等重启（最多 60 秒）
> 再读回校验。

**再一起跑**，所有手上电，等 40 秒：

```bash
python no_load_aging.py --duration 2h          # 自动扫描, 扫到几只跑几只
```

**起跑是逐只串行的**，日志里会看到后面的手打「排队中, 等前面的手连接就位」。这是必须的：
SDK 的连接握手会把已连上的手的订阅回调饿死（能饿十几秒，日志报 `lagged N messages`），
并发起跑的话先连上的那只会等不到反馈帧而自判失败。连接 / 使能 / 回零串行，跑起来之后
各跑各的。所以 4 只手启动大概要多花十几秒，属正常。

每只手一个线程各跑各的，各自读自己的手型和在线关节，左右手混跑没问题。
一只手掉线不影响其他手（起跑前失败会停全场，让人当场发现；跑起来之后掉线只停它自己）。
退出码：全部正常 = 0，有手失败 = 1。

> **掉线的那只手不会自动重连**，它的老化就此结束，其余手继续跑完。所以 2 小时的长跑
> 建议中途看一眼。

> 一次运行里所有手共用同一组命令行参数（频率、增益、行程缩放等）。**例外是限位表** ——
> 那个按每只手的 SN 各认各的，见第 9 节。要给不同的手跑不同的动作参数，就开多个窗口，
> 每个 `--address` 指定一只手。

**多只手同跑时留意母线电压。** 实测同一条命令下，两只手的表现可能差很多：

```
[WH2JA01260724017] 整场汇总: 母线最低 10.8V, ... 全程触发过 限流(16 个轴)
[WH2JA01260723023] 整场汇总: 母线最低 11.4V, ... 全程无限幅
```

同样 20% 行程，一只干干净净，另一只母线低 0.6 V 就开始掉扭矩、大面积限流 —— 而那只手
**单独跑时母线有 11.4 V、一个限流都没有**。这是供电/线束的余量问题，不是脚本问题。
多只手一起长跑前，先各自单跑一轮对比母线最低值，差得多就检查电源和接线。

## 8. 出问题了

| 现象 | 怎么办 |
|---|---|
| 没扫到手 | 手上电要等约 40 秒。检查网线、交换机、电脑网卡是不是 `192.168.1.100/24` |
| 扫得到、ping 得通、就是连不上 | **多半是上位机正连着这只手**，见下面「连不上但 ping 得通」 |
| 两只同侧手一起上电都连不上 | 撞 IP 了，按第 7 节逐只配。脚本会在扫描后直接拦下来并列出撞在一起的 SN |
| `Failed to get Zenoh capabilities` + 日志里 `close message (reason 3)` | **reason 3 = MAX_SESSIONS，设备并发会话满了**，不是网络问题。断电重启没用。见下 |
| 改完 IP 连不上新地址（脚本报超时、退出码 2） | IP 可能已经写进 flash 了。再等 40 秒，用 `python set_hand_ip.py --address 新IP:7447 --show` 确认；读得到就是成功了，读不到再用旧 IP `--show` 看是不是没切过去 |
| `set_hand_ip.py` 说「扫到 N 只手」 | 改 IP 必须一次只上电一只。断掉其余的手，或用 `--address` 指定 |
| `目标 IP 必须和当前 IP 在同一 /24 网段` | 固件子网/网关写死，只能在 `192.168.1.x` 里挑，推荐 `.112` / `.113` / `.114` |
| `等不到 joint_states 反馈帧` | 手没起来完或网络不通。等 40 秒再试，加 `-v` 看细节 |
| 「掉拍」不为 0 | 电脑跟不上。关掉占 CPU 的程序；笔记本插电源、电源模式设「高性能」 |
| 母线电压掉到 10 V 以下 | 多关节堵转或撞在一起了。停下来降 `--amp-scale`，检查手指有没有互相干涉 |
| `--dry-run` 出现 `<<< 超限!` | 行程超出限位表，多半是限位表跟这只手对不上，见第 9 节 |
| 手指互相剐蹭 | 降 `--amp-scale`。空载老化确认四指已撑成扇形，或用 `--abd-mode preset` |
| 跑着跑着掉线 | 掉线的手不会自动重连，老化就此结束。加 `-v` 复跑看是网络断还是设备侧报错，同时看母线电压有没有塌 |
| 单指老化动作看着没做全 | 正常，目标角被限位削了。启动提示里的「限位削幅」会说明削到多少（拇指 cmc_flex 上限只有 +74°） |
| 状态行冒出「限流 / 错误码」 | 见下面「状态行里的限幅和错误码怎么读」 |
| 某个轴看着没动 | 看收尾的「跟踪检查」那行 —— 命令 vs 实际行程。外展这类小振幅轴常被静摩擦吃掉 |
| 反复报 `限位`，或 `限位 + 限流` 同时亮 | 设计限位比这只手真限位宽，命令过界顶死了。用 `--export-limits` 测出真限位，见第 9 节 |
| `SET error: set failed: InternalError` | 订阅流和 SET 查询并发下的偶发失败，设备侧没故障。脚本会自动退避重试 4 次；日志里出现「重试成功」就是这个 |

### 连不上但 ping 得通

扫得到、ping 得通、就是连不上，报 `Failed to get Zenoh capabilities`——
**先看 SDK 日志里的 `close message (reason N)`**，那才是真正的原因（脚本会自动提示，
加 `-v` 看完整日志）：

| reason | 含义 | 怎么办 |
|---|---|---|
| **3 = MAX_SESSIONS** | 设备的并发会话满了 | **先看上位机是不是正连着这只手** —— 见下 |
| 其它 | 见 zenoh 的 `transport/close.rs` | 加 `-v` 复跑，把完整日志报给无极 |

**最常见的就是上位机占着。** 设备同时只招待很少几个客户端，上位机连着的时候 SDK 就
连不进去，报的正是 reason 3。现象很有迷惑性：扫描照样扫得到（扫描不占会话）、ping 也
通、看着一切正常，就是 `connect()` 进不去。**断电重启没用** —— 重启完上位机会自动连
回去，槽位照样被占。先在上位机上断开这只手，再跑脚本。

同理，两个终端窗口各跑一个脚本连同一只手，第二个也会撞上这个。

> 顺带：SDK 内部一次 `connect()` 会做最多 10 轮握手（日志里的 `Zenoh capability
> attempt N`），所以 `--address` 直连、`retry_count=0` 都绕不开这个上限，别指望靠重试
> 挤进去。

### 状态行里的限幅和错误码怎么读

一切正常时状态行只有电压电流温度。**一旦哪个关节报限幅或错误码，这行会自动接上后半截**：

```
已跑 12 分钟 | 母线 10.2V(最低 9.9V) 电流峰 2.98A 温度 58℃@index_J3(最高 58℃) | 限流: index_J3, middle_J3 | 限位: ring_J1 | 错误码: index_J3=0x0003(Enc1BitRate/Warning)[Fault]
已跑 13 分钟 | 母线 11.6V(最低 9.9V) 电流峰 1.20A 温度 57℃@index_J3(最高 58℃) | 限流: 本分钟内 2 个关节曾触发 | 错误码(已自清): index_J3=0x0004(Enc2BitRate/Warning)
```

| 字段 | 意思 | 一般是什么原因 |
|---|---|---|
| `限流: 关节名` | 该关节正卡在扭矩上限（`--iq`）上出不来 | **最值得看的一个。** 堵转、撞到别的手指、负载太重。多个关节同时限流会把母线拉塌 |
| `限位: 关节名` | 撞到固件里的软限位了 | 轨迹超出这只手的真限位 —— 限位表是设计值，见第 9 节。先 `--dry-run` 看余量 |
| `限速: 关节名` | 速度被限住 | 频率或行程给太大，降 `--amp-scale` |
| `错误码: 关节名=0x____(名称/级别)[状态字]` | 该关节**此刻**的错误码，已按官方码表解码 | 见下 |
| `错误码(已自清): 关节名=0x____` | 这一分钟内闪现过、现在已经自己恢复 | 见下 |
| `本分钟内 N 个关节曾触发` | 踩过限幅但现在松开了 | 同上 |

**错误码非零 ≠ 故障。** 这个字段是固件原样上报的 16 位值，里面混着告警位。
**SDK ≥ 2026.8.17 起脚本会自动解码**，括号里就是官方码表的名称和严重度：

```
错误码(已自清): middle_J3=0x0003(Enc1BitRate/Warning)
```

`Warning` 级不用停机。想看完整解释（原因 / 处置）自己查：

```python
python -c "import wuji_sdk,json; print(json.dumps(wuji_sdk.WujiHand2.describe_error(0x0003), ensure_ascii=False, indent=2))"
# → name=Enc1BitRate severity=Warning clear_policy=AutoClear
#   desc=编码器1 bit 标志率偏高  resolution=检查编码器1本体/磁铁安装
```

老版本 SDK 没有 `describe_error`，脚本自动退回只打十六进制，不会报错。多个码会按位
或在一起（`0x0003` + `0x0004` 显示成 `0x0007`），或出来的组合码可能查不到名字。

**别看到非零就停机**，先看下面几条真正说明问题的：

- **限流 + 母线塌到 10 V 以下** → 堵转或手指撞在一起。停机、降 `--amp-scale`、查干涉。
- **限位反复触发** → 限位表跟这只手对不上，按第 9 节改 `joint_limits.json`。
- **温度一路爬 + 持续限流** → 该关节长期吃满扭矩，检查治具和负载。
- **错误码 + 完全没有限幅标志 + 电流很低** → 多半是告警位（`0x0003` 就是这种），
  记下哪个关节，长跑结束看整场汇总即可。

**四个脚本的输出是同一套**（这段逻辑在 `aging_common.py` 里，不在各脚本），但
`限流` 该不该出现，按脚本不一样：

| 脚本 | `限流` 正常吗 |
|---|---|
| 空载老化 | **不正常。** 空载不该吃满扭矩，出现就是手指互相剐蹭或某个关节卡住 |
| 单关节老化 | **不正常**，同上。多半是走到限位顶死了，同时会看到 `限位` |
| 带载老化 | **抓握相位出现是预期的** —— 握紧圆柱本来就靠扭矩上限顶住。但**张开相位不该有**，张开时还限流说明手指卡在治具上了 |
| 单指负载老化 | **保持相位（J1 屈到 +90° 停住）出现可能是正常的**，负重块的力矩就压在扭矩上限上。摆动段出现才要查 |

不确定算不算正常，就看母线电压和温度：只要电压稳在 11 V 以上、温度走平，限流就是
在按设计吃扭矩；电压往下掉或温度一路爬，那就是堵着了。

跑完那行 `整场汇总: 母线最低 __V, 电流峰 __A, 温度最高 __℃, 全程无错误码` 是**整场的**
台账 —— 2 小时的日志没人会翻，中间闪现过的错误码都攒在这一行里。

## 9. 限位表，和与上位机剩下的差异

**`joint_limits.json` 是设计值**，来自机械图纸，不是某一只手的实测限位 —— 它只是所有
手的共同兜底。

上位机会读固件里每只手自己的真限位（`ps_final_pos`）；公开 SDK 的 `get_soft_limits()`
只挂在一代 `WujiHand` 上，**`WujiHand2` 没有这个方法**（`JointHandle` 也只有
`effort_limit / error_code / status_word`），所以本工程读不到，只能靠下面的实测标定。

**限位表按每只手自动挑**，优先级：

```
--limits 显式指定  >  limits_<SN>.json (本手实测)  >  joint_limits.json (设计值兜底)
```

后两者都在「当前目录 → 脚本所在目录」两处找。所以一拖多时几只手可以有的已标定、
有的没标定，各用各的，命令不用改。

### 用 `--export-limits` 实测出这只手的真限位

设计限位比实际宽的话，命令角会过界、被固件夹住 —— 状态行报 `限位`，严重的会
`限位 + 限流` 同时亮（顶死堵转）。这时候可以把真限位**测出来**：被夹住的轴，它实际
走到的极值就是这只手的真限位。

```bash
# 1. 满行程跑一轮采集(顶限位正是采集所需, 别加 --amp-scale)
python single_joint_aging.py --amp-scale 1.0 --duration 75s --export-limits
#    → 写出 limits_<SN>.json

# 2. 之后正常跑就行, **不用写 --limits** —— 脚本按 SN 自动认这只手的表
python single_joint_aging.py --duration 2h
```

启动日志会**逐手**写明用的是哪份表：

```
[WH2JA01260724017] 限位表: limits_WH2JA01260724017.json (本手专属, 5/20 轴为实测真限位, 其余仍是设计值)
[WH2JA01260723023] 限位表: joint_limits.json —— **设计值, 不是这只手的实测限位**。
                   部分轴可能顶限位; 跑一轮 `--export-limits` 就能标定出 limits_WH2JA01260723023.json。
```

**来一只新手就是这个流程**：直接跑 → 日志提示它没标定 → 想标定就加一次
`--export-limits` → 以后自动生效。用 `--limits` 硬指一份别的手的表时，SN 对不上会告警
（不阻断，可能是有意共用）。

导出文件里每个关节都有 `source` 字段，三种取值互斥：`实测 …(本轮)` = 这轮量到的 /
`实测 …(沿用 …)` = 之前某轮量到的 / `设计值 …` = 从没量到过。迭代多轮也分得清。

**判据是逐「侧」的**：只有「该侧实际没走到命令角超过 2° **且**该轴报过位置限位」才
采信实测值，其余保留原值。不这么判的话，跟得好好的轴每跑一轮就会被往里缩 5°（因为
它的实际极值本来就等于命令极值 = 设计值 − 5° 余量），越缩越窄。

**必须满行程跑才标得出来** —— 带 `--amp-scale` 缩了行程就顶不到限位，量不到东西。这种
情况脚本不会写出空表，而是提示 `未导出限位表: 本轮没有任何关节被限位夹住`。

> **平时跑老化不会产生任何文件。** 只有显式加 `--export-limits` 才写；`--dry-run`、
> Ctrl+C 中断、以及没量到东西这三种情况都不写。标定是一次性动作，除非换了固件或
> 重新校准过关节，不用重导。
>
> `limits_<SN>.json` 已在 `.gitignore` 里 —— 它是逐台设备的现场产物，不进仓库。

实测例子（本工程那只 `WH2JA01260724017`）：

| 关节 | 设计 | 实测真限位 | 差 |
|---|---|---|---|
| `pinky_J3` | -60 ~ **120°** | -60 ~ **102.5°** | 上端窄 **17.5°** |
| `pinky_J2` | **-40** ~ 40° | **-25.5** ~ 40° | 下端窄 **14.5°** |
| `middle_J2` | -40 ~ **40°** | -40 ~ **30.9°** | 上端窄 9.1° |
| `thumb_J4` | **-60** ~ 90° | **-50.9** ~ 90° | 下端窄 9.1° |
| `ring_J2` | -40 ~ 40° | **-32.7 ~ 31.4°** | 两端各窄 7~9° |

换上实测表后满行程复跑：**限位 7 轴 → 3 轴，限流 9 轴 → 6 轴**，`thumb_J4` 那个连续
五轮的顶死消失。剩下的是被夹幅度小于 2° 容差没采到的，再导一轮可继续收敛。

**除了限位来源，和上位机还剩这些差别：**

- **四指二轴摆幅默认 ±20°，上位机默认关。** 唯一一处故意偏离，为的是让每根手指的
  二轴都参与老化。`--abd-swing-deg 0` 复刻上位机默认。换手/换治具要重新标定。
- 不查关节校准标志（公开 SDK 没这个接口），所以请用 `--dry-run` + 小幅试跑代替。
- 单关节 / 单指老化默认跑全部在线关节，上位机是界面上勾选。用 `--joints` / `--finger` 筛。
- 带载老化的抓握姿态是右手采集的，左手没做镜像（和上位机一样），左手的拇指外展方向
  可能需要自己改。
- 没有到位检测、CSV 记录、老化累计计时这些数据功能 —— 这里只做运动。2 小时靠
  `--duration 2h` 一次跑满，不像上位机那样跨多次累计。**判据规格见第 10 节。**

## 10. 合格判定（老化）

**四个老化脚本只跑动作，不产生「合格 / 不合格」结论。** 跑完只会打一句
「N 个运动轴实际行程都 ≥ 命令的 80%」和一份全程错误码汇总 —— 那是给操作员看的
巡检提示，不是判据；代码注释里也写明「判不判停机交给看的人」。

> **位控性能QC 例外 —— `pos_perf_qc.py` 自己出 PASS / FAIL**，判据在第 12 节，
> 不在本节。本节讲的是**老化**要怎么判，两套判据的几何模型不一样，别混用
> （见 12.4）。

老化要做自动判定，按整手 / 整指分两种情况：整手的判据下面给全，自动化设备照此实现
即可；整指目前没有判据。

### 10.1 整手 —— 判据规格

判定不在运动过程中做，而是**先录数据、跑完再离线算**。三步。

#### 第一步：录「未到位差」

老化时每个关节按 `pos = center + amp·sin(ωt+φ)` 来回摆，`center ± amp` 就是这一轮的
**命令端点**。按固定窗口（建议 **1.5 s**，约半个周期）统计该关节这一窗口内实际到达的
极值，与命令端点比：

```
下端差 Δ↓ = max(0, 实际min − 命令下端)     单位 °，到位则为 0
上端差 Δ↑ = max(0, 命令上端 − 实际max)     单位 °，到位则为 0
```

两个都是**短缺量**：关节没摆到命令端点差了多少度。

- 比较基准是**命令端点，不是硬限位**。命令区间已经在限位基础上两端各内收过安全余量
  （见第 4 节），老化本来就故意够不到硬限位，拿硬限位比会永远判不到位。
- `center` / `amp` 用 `--dry-run` 会逐轴打印，也可从限位表 + 第 4 节的余量表自己算。
- 每个窗口每关节记一行，字段建议：时间戳、关节 NID、命令下端/上端、实际 min/max、
  Δ↓、Δ↑、母线电压。落成 CSV 即可，格式自定。

NID 与手指/轴位的对应：`NID = 1..24`，`手指 bus = (NID−1)//5`（0 拇 1 食 2 中 3 无名
4 小），`轴位 S = (NID−1)%5 + 1`（S1 屈伸根 / S2 外展 / S3 中节 / S4 末节；第 5 槽是
触觉，无电机）。

#### 第二步：筛掉不该进统计的数据

| 规则 | 阈值 | 为什么 |
|---|---|---|
| 短跑整段丢弃 | 单次运行时长 < **300 s** | 启动即中断的试跑，不是老化 |
| 开头 warmup 丢弃 | 每次运行前 **60 s** | 避开启动斜坡不稳段 |
| 末尾掉电段丢弃 | 从末尾往回扫，连续命中「整批 Δ > **20°**」或「母线电压跳出 **8~16 V**」的窗口全裁，遇正常窗口停 | 断电/失力是终止性的，脏尾会污染结论；只裁末尾连续坏段，不会掩盖中途的真实问题 |

#### 第三步：判据 —— 指尖线偏差（每根手指）

手指是串联链：根部关节的未到位角会带动整根远端一起转，越往指尖累加越多。所以不能逐轴
看角度，要折算到指尖的**线偏差**：

```
dev = Σᵢ  Lᵢ · sin(从根部累加到第 i 段的未到位角之和)
```

`Lᵢ` 是**相邻关节的轴间距**（真实节段长，不是力臂）。下端用各关节 Δ↓ 算一遍、上端用
Δ↑ 算一遍，取 `worst = max(dev↓, dev↑)`。

展开式与段长（单位 mm）：

```
四指（S2 外展轴老化时锁死、不进链；mcp_flex→pip 两段都只受 δ₁ 影响，合并进 L_S1）:
  dev = L_S1·sin(δ₁) + L_S3·sin(δ₁+δ₃) + L_S4·sin(δ₁+δ₃+δ₄)

  食 / 中 / 无名   L_S1 = 52.15   L_S3 = 29.50   L_S4 = 25.06
  小指             L_S1 = 48.15   L_S3 = 27.50   L_S4 = 25.06

拇指（cmc_flex 与 cmc_abd 隔 14.77 mm 是两个不同点，外展轴真在摆，各段独立）:
  dev = 14.77·sin(δ₁) + 32.50·sin(δ₁+δ₂) + 35.00·sin(δ₁+δ₂+δ₃) + 27.70·sin(δ₁+δ₂+δ₃+δ₄)
```

> **四指那条式子的前提是外展轴不摆。** 本工程默认 `--abd-swing-deg 20`（见开头的「唯一
> 一处故意不一致」），外展轴在动，四指的链就不是上面这三段了。**要按这套判据出结论，
> 请用 `--abd-swing-deg 0` 跑**，否则得先把外展轴也按拇指那样列进累加链。

拿到每个窗口每指的 `worst` 之后，两步判：

**① 单帧物理门**：该窗口内任一关节 `Δ↓ > 10°` 或 `Δ↑ > 10°` → **整个窗口丢弃**。

正常老化单关节最坏约 3°，出现 ≥16° 的都是换向暂态或传感器瞬时异常产生的非物理值，
经累加式放大会变成十几 mm 的假偏差。这一刀不切会大面积误判不合格。报告里要写明丢了
多少个窗口 —— 丢得异常多本身就是需要查的信号。

**② dev 三档分布**（在过门后的窗口上，每指独立统计）：

| 档 | 范围 | 合格条件 |
|---|---|---|
| A 好 | `dev < 2 mm` | 占比 **> 90%** |
| B 临界 | `2 ≤ dev < 4 mm` | 占比 **< 10%** |
| C 差 | `dev ≥ 4 mm` | 次数 **< 3** |

C 档的「次数」要**把连续相同的值合并为 1 次**：到位检测有周期保持，一个坏周期的值会
横跨 2~3 个窗口重复出现，不合并会把 1 个坏点算成 3 个。

三条全满足 → 该指合格。

```
整手 PASS  ⟺  5 根手指全部合格
```

#### 阈值出处

| 阈值 | 值 | 依据 |
|---|---|---|
| 指尖偏差上限 | **2 mm** | 整手的指尖 ±2 mm 精度指标，唯一有硬指标的一个 |
| C 档下界 | 4 mm | 实测调出 |
| A 档占比下限 / B 档上限 / C 档次数 | 90% / 10% / 3 | 实测调出 |
| 单帧物理门 | 10° | 真实最坏 ~3°、脏帧 ≥16°，10° 一刀两边都不误伤 |
| 短跑 / warmup / 掉电特征 | 300 s / 60 s / 20°、8~16 V | 实测调出 |

除 2 mm 之外都是经验阈值，实现时做成可配置。

> **不要用「逐关节未到位角」直接判合格。** 逐轴看角度会比指尖精度严得多，典型误判是
> 某个末节关节长期差 1.4° 就被判死，而它对指尖的影响不到 2 mm、功能完全正常。逐关节
> 数据留着排查用（定位是哪根轴主导了偏差），不进整手结论。

### 10.2 整指 —— 目前没有判据

`thumb_aging.py` / `four_finger_aging.py`（5 槽位同型指治具）和 `single_finger_aging.py`
**都没有自动合格判定**，现状是人看日志：跑完无错误码、行程跟得上、无异响即放行。

10.1 那套算法也套不过来 —— 累加链和段长是按整手 5 指几何定的，5 个独立槽位的同型指
治具用不上。

> **整指的验收判据待定义。** 自动化设备如需整指出结论，请与我们确认判据后再实现，
> 不要照抄 10.1 的公式和数值。

## 11. 改成自己的

`aging_common.py` 是五个脚本共用的骨架：连接、使能、回零、200 Hz 下发、安全停机、
多手编排都在里面。**改动作不用碰它**，只要写一个 `build_profile()`：

```python
def build_profile(ctx):
    return Profile(
        name="我的老化",
        kp=5.0, kd=0.1, iq=1.0,
        center=[...],          # 20 个, 启动回零斜坡的终点 = 运动 t=0 的位置
        motion=my_motion,      # (t, env) -> (positions[20], velocities[20])
        enabled=[True] * 20,   # 哪些关节参与
        stop_style="sine",     # "sine" 收摆后回零 / "freeze" 冻结目标后回零
    )
```

- `t` 是从运动开始起算的秒数，**一直累加不取模** —— 正弦相位靠它连续，取模会在跨周期
  时产生相位跳变，多关节叠加就是每几秒「打嗝」一次。
- `env` 是振幅包络 0~1，骨架用它做起步渐入和停止收摆。**只乘在振幅上，别乘中心位置。**
- 关节下标是 0~19，`k//4` 是第几根手指，`k%4` 是该指第几个轴。
  固件 NID 用 `flat_to_nid(k)` 换算（每根手指占 5 个号，第 5 个是触觉节点没有电机）。

**这四条别绕过**（骨架里已经做好了）：

1. **使能之前先把当前实际角当目标发出去。** 固件里 MIT 的目标角上电默认是 0，
   不预置就使能 = 20 个关节同时从当前姿态弹向 0 位，母线电流尖峰 → 欠压 → 整手掉线。
   这条最容易踩。
2. **目标角的种子取 `joint_states().position`（关节侧角度）**，不能用电机侧的多圈角度，
   那个拿来当目标会把关节甩飞。
3. **没参与的关节要填保位值（使能瞬间的实际角），不能填 0**，填 0 会把它们拉向零点。
4. **任何退出路径都要回零 + 断使能**，老化循环是无限的。

**不是「一个无限循环的波形」的工序**（位控性能QC 就是：逐指使能 → 测一段 → 算个数 →
换下一指），装不进 `motion(t, env)`，改用 `Profile.sequence` 钩子接管整个流程：

```python
def sequence(runner, prof):
    for f in fingers:
        runner.scope(prof, enabled_of(f))        # 切使能范围(自动走完预置保位再通电)
        runner.ramp_phase(prof, center_pose, 1.5)  # 从当前实际角斜坡到某个姿态
        runner.run_phase(prof, traj, 7.0)          # 跑一段固定时长的轨迹
        runner.unscope(prof)                       # 断开这一批

def build_profile(ctx):
    return Profile(..., sequence=sequence, disable_all_on_exit=True)
```

- `sequence` 非 None 时，骨架跑完 `_configure()` 就把控制权交给它，**不走**默认的
  「预置使能 → 回零 → 无限循环 → 停机序列」四段链；`_shutdown()` 照常兜底。
- `run_phase()` / `ramp_phase()` 返回 `False` 表示收到停机请求（Ctrl+C / `--duration`
  到时），**拿到 False 就该立刻收尾**，别再往下测。
- 逐批使能必须用 `scope()`，它每次切换都重走安全纪律 #1 和 #3。自己调
  `hand.enable()` 就绕过了预置保位，等于让那一批关节从当前姿态弹向 0 位。
- `disable_all_on_exit=True`：逐批使能的流程收尾时 `enabled` 里只剩最后一批，
  按它 disable 会**漏掉前面几批**，所以要整手断。
- `motion` 仍要给一个能代表行程的波形 —— `--dry-run` 的行程表和限位余量是采样它算的。

## 12. 位控性能QC 的判据

本节是 `pos_perf_qc.py` 的验收规格，对齐上位机 `PosPerfQcWorker`。
**第 10 节那套是老化的判据，两者的几何模型不一样，别混用**（见 12.4）。

### 12.1 测什么

逐指测，每指两趟。**逐指而不是整手一起**：20 轴齐动的母线电流会把扭矩顶到限流，
限流下量到的延迟和静差全不可信；一次 enable 20 个关节还偶发会话卡死。上位机同样逐指跑。

| | 第一趟：跟踪延迟 | 第二趟：静态静差 |
|---|---|---|
| 动作 | 该指各轴同时走 1 Hz 正弦，相位错开 90° 防撞 | 逐轴单独推到行程两端保持，其余轴守中心 |
| 量法 | **锁相**解出位置滞后的相位，折成毫秒 | 软件积分压掉静差后的残差，按力臂折成指尖偏差 |
| 判据 | 每轴 < **45 ms** | 指尖上/下端都 < **2 mm** |

```
整指合格 ⟺ 各轴延迟都过 且 指尖两端都过
整手 PASS ⟺ 所测手指全合格
```

**四指二轴（mcp_abd）不测** —— 锁在中心不动，和上位机一致。只有拇指测全 4 轴。

**为什么第二趟要跑软件积分**：固件 MIT 只有 P 和 D，**没有积分项**，稳态一定留一截
静差。上位机在自己这一侧跑积分（ki=5，力矩钳 0.3 A）把静差压掉，量到的是「连积分都
压不掉的那部分」。`--ki 0` 可以看纯 P 控的静差，但那不是判据。

**为什么第一趟用锁相而不是找峰值求时间差**：锁相用上了整段每一个采样点，单点噪声和
偶发掉帧都被平均掉。实测（模拟一阶环节，理论滞后 30.61 ms）解出 30.61~30.85 ms。

### 12.2 怎么读结果

```
[WH2JA...] === 食指 (index) ===
[WH2JA...]   [1/2] 跟踪延迟 1Hz × 4 周期 (7.0s)
[WH2JA...]     index_J1       延迟   30.8ms  跟踪  98%  静差↑  +0.38° ↓  +0.40°  OK
[WH2JA...]     index_J3       延迟   30.6ms  跟踪  99%  静差↑  +0.38° ↓  +0.41°  OK
[WH2JA...]     index_J4       延迟   30.8ms  跟踪  98%  静差↑  +0.38° ↓  +0.40°  OK
[WH2JA...]   食指: 最大延迟 30.8ms, 指尖静差 ↑1.22mm ↓1.30mm → **PASS**
[WH2JA...] 位控性能QC 结论: **PASS**
```

| 字段 | 意思 |
|---|---|
| `延迟` | 锁相解出的位置滞后（ms）。判据①，门限见 12.3 |
| `跟踪` | 反馈幅度 / 命令幅度。**< 20% 该轴判「判不了」** —— 卡死的轴锁相会解出一个随机相位，不拦就有一半概率假合格通过 45 ms 门限 |
| `静差↑ / ↓` | 该轴在行程上端 / 下端的稳态静差（度）。折算成指尖偏差后才进判据② |
| `限位 / 限流` | 该段踩到了固件的限幅标志。**踩到限位 → 该指判「判不了」**，见 12.3 |

**三种结论，不是两种**（上位机只有 PASS / FAIL）：

| 结论 | 退出码 | 意思 | 怎么办 |
|---|---|---|---|
| `PASS` | 0 | 合格 | 进空载老化 |
| `FAIL` | 1 | 不合格 | 这只手的位控性能不达标 |
| `INVALID` | 3 | **判不了** | 测量条件不成立，结论无效。**不是不合格**，按日志里的理由处理 |
| — | 2 | 连接或参数错 | 结论不可信 |

判「判不了」的三种情况：① 某轴被限位夹住；② 某轴跟踪率 < 20%；③ 带了 `--amp-scale`。

`--out qc.json` 写出的 JSON 里，字段名对齐上位机 `PosQcJointResult` /
`PosQcFingerResult`（`lagMs` / `steadyErrUpDeg` / `steadyErrDnDeg` / `tipUpMm` /
`tipDnMm` / `verdict` / `reason`），自动化设备直接取数。

### 12.3 与上位机的两处差异 —— 上产线前必须先对一遍

**差异 1：限位读不到真值，所以多了「判不了」这个结论。**

上位机逐轴读固件的 `od/ps_final_pos_{down,up}_rad` 拿这只手的真限位；公开 SDK 没有
原始对象字典读接口（`WujiHand2` 只有 `effort_limit / error_code / status_word`），
所以本脚本用**设计限位**或 `limits_<SN>.json`（第 9 节）。

后果比老化严重得多：设计值比真限位宽时，命令角会过界被固件夹住，那一段量到的「静差」
是「命令角 − 限位角」而不是伺服误差。实测把某轴真限位掐到 ±10°、命令 ±82.5°，量出
静差 72.5°、指尖 **134 mm** —— 照上位机的两种结论，这只手会被判成**不合格**，而它
唯一的问题是限位表没标定。所以本脚本盯 `position_limit_active`，一旦夹住就判
「判不了」。**宁可要人来看一眼，不能误杀好手。**

> 来一只新手的流程：先跑一轮
> `python single_joint_aging.py --amp-scale 1.0 --duration 75s --export-limits`
> 标定出 `limits_<SN>.json`，之后 QC 按 SN 自动认这只手的表。

**差异 2：45 ms 这个门限里含约 8 ms 的 Qt bridge 测量路径偏移，而 SDK 路径没有。**

上位机源码原话：

```
lagMsMax = 45.0f;   // pass gate: lag (ms). 45 = real PD lag ~31ms + ~8ms
                    // Qt-bridge measurement-path offset (vs SDK) + margin.
```

括号里的 `vs SDK` 就是说 SDK 这条路径**没有**那 8 ms。所以照搬 45 会比上位机
**松约 8 ms**，等效门限约 37 ms。

默认仍取 45（产线规格上写的那个数），脚本启动时会打这条提示。
**这个数必须在同一只手上与上位机对一遍**再拿去当判据：跑
`python pos_perf_qc.py --finger index`，把日志里某一轴的延迟值跟上位机「位控性能QC」
Tab 同一轴的数对一下，差多少就把 `--lag-ms-max` 定到多少。
跟四指外展摆幅一样，是要现场标的量，不是照抄的常数。

### 12.4 指尖折算：和第 10 节是两套不同的几何

两处都叫「指尖偏差（mm）」、都用 2 mm 当门限，但**算法不同，数值不能互相顶替**：

| | 第 12 节（位控QC） | 第 10.1 节（老化） |
|---|---|---|
| 折算什么 | 每轴**静差**各自对指尖的力臂投影 | 根部未到位角**带着远端一起转**的累加偏差 |
| 几何量 | 各轴到指尖的**力臂** `L_ARM[]` | 相邻关节的**轴间距**（节段长） |
| 公式 | `hypot(Σ 屈伸分量, Σ 外展分量)` | `Σ Lᵢ·sin(从根部累加到第 i 段的角度和)` |
| 激励 | 专门的静态保持（kp 8 / 逐轴隔离） | 老化波形顺带录的（kp 5 / 0.3 Hz / 全轴同动） |
| 数据来源 | `PosPerfQcWorker` 的 `L_ARM[]`（hand2_beta URDF） | 机械图纸的段长 |

两者都对，是因为在回答不同的问题。**改其中一套的数值不要顺手改另一套。**

### 12.5 算法的验证情况

`wuji-sdk` 是 Windows wheel，开发机上跑不了，所以算法是在一个**模拟手**上验的 ——
一阶伺服 + 常值重力扰动 + 机械限位，理论值可解析算出来对照：

| 验的东西 | 理论值 | 实测 |
|---|---|---|
| 锁相解出的跟踪延迟 | 30.61 ms | 30.61~30.85 ms（误差 ≤ 0.15 ms） |
| 静差测量（`--ki 0` 纯 P 控） | 0.4440° | 0.4440° |
| 软件积分把静差压小 | — | 0.444° → 0.270° |
| 扰动超出积分钳位 → 指尖 15.5 mm | — | 判 FAIL |
| 真限位窄于设计限位 → 被夹住 | — | 判 INVALID（不是 FAIL） |
| 拇指 J2 负侧按端点值内缩 5% | −74.8125° | −74.8110° |

> **模拟手验的是算法，不是这只手。** 波形、增益、判据逻辑都走通了，但
> **45 ms 那个门限仍须在真机上与上位机对一遍**（见 12.3 差异 2）。
